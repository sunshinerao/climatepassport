# Climate Passport 功能开发需求说明书 V2

日期：2026-09-18。状态：当前下一阶段开发基准；新增能力为目标需求，尚未实施。本文承接 [V1既有需求编号](CLIMATE_PASSPORT_FUNCTIONAL_REQUIREMENTS_V1.md)、[当前安全与证书差异](REQUIREMENTS_IMPLEMENTATION_GAP_AUDIT_20260918.md)，合并 `ref_docx` 三份programme输入。来源、冲突裁决及代码证据见 [需求提炼与兼容分析](PROGRAMME_REQUIREMENTS_SYNTHESIS_20260918.md)。

**边界修订 V2.1，按用户最新确认：Programme业务层由各programme独立开发、维护并对接CP，不属于CP的开发交付。** 原版将项目专属工作区、年度激活、支持工单和Credit等列入CP工单，范围过宽，现已移出。来源文件中“可托管CP项目模块”的建议不再作为本项目开发要求。下文区分CP通用能力、外部业务要求和联合验收场景，不能把场景中的全部步骤变成CP开发任务。

## 1. 定位和本轮结论

Climate Passport是面向多个programme的数字基础底座，提供统一身份与主档、范围授权、通用参与事务、受控记录/证据存储、版本和同意管理、授权访问、可信行动记录及凭证。Programme自行开发业务规则、状态机、审核流程、业务数据模型与页面，通过API/SDK/事件接入CP。CP核验调用权限、业务结果来源和平台安全约束，但不开发或运行项目专属业务模块。一个programme的运营、审批或赞助关系不能获得另一programme的数据权。

身份、录取、出席、贡献核验、能力认证、公开发表和商业/治理资格是独立事实。CP不因登录、付款、报名、签到、导师好评或作品公开而自动授予其他状态。

本轮补项目隔离、机构代表权、通用私密记录/证据版本、同意/撤回、外部结果接入和可靠接口。不同programme复用底座，不复制CP拥有的账户、凭证和已选择由CP承载的交易；其自身课题、业务会员、任务书、工单、信用评价和网站仍由自身系统拥有。

### 新能力进入CP的准则

1. 去掉任何programme名称后，仍可用稳定领域概念解释并服务未来接入方；多个项目都需要某业务流程，也不自动意味着CP要承包该流程。
2. 能用通用API、授权、记录、证据、凭证或可靠性能力交付，不需要认识七步法、席位、Credit权重或特殊编辑流程。
3. 明确CP唯一权威字段及外部业务权威字段；只同步必要引用、版本、授权和结果，不复制全套业务数据库。
4. CP配置仅控制客户端、scope、字段、资源限制、通用凭证/参与规则和平台安全；不得用programme配置包、插件或通用工作流引擎绕回承载个性化业务。
5. 新接入方遵循既定契约时，无须新增其专属CP模块、页面、表或品牌条件分支；确需新共用能力时先独立评审复用价值。

## 2. 三层职责及单一写入方

| 层 | 拥有的事实及职责 | 约束 |
| --- | --- | --- |
| Core共享服务（CP开发） | 账户/Passport ID、Person/Institution、范围授权与同意、CP承载的通用报名/容量/核验、受控记录/证据版本、外部决定回执/审计、授权访问、凭证和长期记录 | 不开发项目课程、录取评审、作品编辑、席位激活、Credit、支持工单等业务 |
| Programme业务层（外部自主开发） | FS号召/课题/学习/导师/编辑系统；SHCW举办申报和年度运营；CV成员/席位/年度激活/任务书/支持/Credit/Standing系统 | 各programme自己开发和维护，拥有其业务模型、状态机、数据库和审批界面；仅通过受限契约调用CP，不在CP新增专属模块 |
| Channel体验/内容层（Programme开发） | 项目网站、业务工作区、运营后台、内容编排、策展/推荐位 | programme业务字段由programme维护；CP权威字段只作受控投影，不能反向覆盖或用缓存自判权限 |

### 数据归属细化

- SHCW举办申请、Speaker/Venue/Volunteer征集审核、退修/拒绝、候选池、谈判、排班、报价和内部意见留SHCW业务域，不能写入CP行动履历。正式获批活动才可建私有关联，发布由来源版本控制。
- CP已承载的活动参与报名、LE申请、证书申请继续保留，不能按“Application”名称一刀切。线上Call enrollment、现场录取、会员申请也是不同目的和容量。
- FS拥有Call/Lab/Inquiry、学习任务、导师分配、投稿评审及编辑发布系统。需要时调用CP通用记录/附件版本与同意服务；CP保存受控资源及经授权的版本化决定回执，不接管课题模型、审核队列和编辑流程。业务发布决定归FS，CP资源能否公开仍必须通过CP当前同意和访问校验。
- CV拥有席位、年度激活、Offer-Need、任务书、支持工单、Credit/Standing及申诉全过程。CP只提供主体引用、委托/访问授权、通用证据、必要结果接入和可选凭证；不建立同名业务表或执行该工作流。业务激活状态可作为外部授权依据，但CP只保存所需的有期限授权投影。
- Person/Institution是可复用主档，不是公开全库。别名/旧引用可以兼容解析，但任何解析、搜索、导出仍须权限。私有来源快照不自动覆盖主档。

## 3. 领域概念与数据约束

以下区分CP对象与外部概念；外部对象仅允许映射稳定sourceRef/schema/version及必要结果，不是CP建表清单。实施先完成字段所有权ADR；CP内同一事实只保留一个权威记录，不能同时创建两套活动、报名或履历。

| 对象 | 关系与最小约束 | 现有模型处置 |
| --- | --- | --- |
| Tenant / Programme / Edition / Channel | Tenant为管理隔离范围，不等于Institution；Programme为业务范围，可含年度Edition；Channel为调用客户端/展示入口，多对多授权绑定而非权限继承 | 新增范围模型；CFA可作集合引用，不凭集合关系授予FS私有权限；不得复用LE Program作全平台租户 |
| AccessMembership / ScopedRoleAssignment（CP） | subject、scope、action、grantor、依据/源版本、有效期及撤销；仅表示CP服务访问授权，不表示主理人/学员业务资格 | 兼容UserRole和manager/verifier关系，业务会员与年度资格由外部决定，不直接放宽旧接口 |
| InstitutionRepresentation / Claim / MergeAlias | 人员代表机构的动作和期限；本人认领证明；合并决策与可解析旧引用 | PersonAffiliation不是委托；Organization/Institution显式适配，不用同名自动合并 |
| SourceObjectMapping / Revision / Receipt | sourceSystem+sourceEditionRef+sourceObjectId唯一，绑定Programme，记录源版本、权威字段、应用状态与CP引用 | 新SHCW优先Activity逻辑入口；Event旧ID通过映射适配，不双写两条可交易记录 |
| ActivitySeries / Occurrence / AdmissionPolicy | 每期独立时区、资格、名额、录取/出席；系列修改不能覆盖历史；独立审批、发布、进程、可见性、报名模式 | DateSlot仅日期槽，不能直接当完整期次；既有Activity/Event保持来源和引用 |
| ExternalTaxonomyRef（CP引用） | 接收外部类型/标签ID、版本及获授权名称，按核心活动引用去重 | Cluster/Track结构、主协同约束及年度归属由programme实现，CP不建CV分类规则引擎 |
| Call / Lab / Resource / Node（外部） | 业务模型、多对多、七步关系、城市展示在FS；CP只接稳定外部引用和必要参加/授权快照 | 不在CP创建专属Call-Lab/课程/CMS体系 |
| Enrollment / Registration / Attendance | enrollment目的+主体唯一；Call参与与现场Occurrence报名分离；资格/规则快照；出席独立更正 | 复用Activity/LE交易服务；举办申报不入本模型；不要扩大User唯一性为一人只能一个角色 |
| ScopedRecord / CollaborationGrant（CP）；Inquiry / ActionPlan（外部） | CP提供有scope/owner/sourceRef/revision的私密记录和分享原语；课题问题/目标、七步任务、双方行动及截止业务在programme | 外部记录不强绑假Activity；既有ActivityTask保留，不扩为FS/CV专属任务产品 |
| Asset / EvidenceVersion / SubmissionVersion | 受控存储key、来源、hash、实际MIME/大小、扫描状态、衍生依赖；版本不可变，授权可变 | ActivitySubmission的fileUrls/可变text不是安全发表模型；用适配引用迁移，不把旧附件默认公开 |
| ExternalDecisionReceipt（CP）；Review / Appeal（外部） | CP校验被授权来源/签署者/对象版本/用途/有效期，保存最小决定回执；业务审核、分配、退修、申诉及正文在programme | 外部approved不等于CP能力核验；CP自有证书/核验审批继续独立，不新增项目编辑审核工作台 |
| GuardianLink / Consent / Publication | 有效关系与独立意愿；用途/频道/字段/版本/期限；publishedVersion与stateRevision | 新增版本授权机制；Portfolio token、PROJECT表单同意和certificate.publicVisible保留原语义，不充当无限授权 |
| Contribution / Verification / RecordProjection | Person或Institution、多角色事实、发生状态、证据、声明/评定等级、更正/撤销链 | 映射到既有Participation/Achievement/Milestone/Portfolio，避免第二套完整履历；可新增事实层但派生不双计 |
| Seat / AnnualActivation / CreditAssessment / Standing（外部） | 由CV自行实现；CP仅按明确用途接收授权/评价结果的最小引用和版本 | 移出CP开发、数据库领域模型及菜单；外部Credit不写User.points或变为全局信用 |
| SupportRequest / SupportDelivery / OfferNeed / Feedback（外部） | 支持类别、双方任务、预算、SLA、跟进与服务评价由programme实现 | CP可提供现有通用通知/证据/审计接口；不开发支持工单、引荐或运营CRM |

新私密对象至少有稳定ID、tenantId、programmeId、必要editionId、ownerSubjectRef、createdBy/实际代理者、时间、revision、归档/删除状态。所有关联都需校验同范围或明确跨范围授权，不能只看请求里带了programmeId。邮箱不是永久身份键；UTC存储与当地IANA时区同时保留。对外稳定opaque引用与内部数据库ID分离。

版本不可变不等于个人材料永久保存；删除按批准政策处理正文与衍生文件，可在最小审计/保留范围内保留撤销或删除标记。

## 5. 关键状态与安全不变量

### 5.1 作品发表

这是CP受控资源的通用访问安全要求，不是CP开发作品编辑系统。Programme提供获授权来源的版本化发表决定；CP验证决定回执及当前同意。Programme负责稿件评审、退修、选择和页面；CP有独立安全拒绝权，外部approved不能覆盖Private或已失效许可。

每次公开读取满足：`authorIntent == PUBLIC`，当前所读不可变版本已批准，必要署名/共同作者/素材/监护许可仍有效，Publication有效，频道在范围内，未被暂停/撤回/删除。项目发表通过不等于专业认证、学术认证或地方行动许可。

| 情况 | 行为 |
| --- | --- |
| Private + 审核通过 | 不公开，也不能通过导出/预览旁路取得公开URL |
| Public + 待审/退修/拒绝 | 当前版本不公开 |
| 旧版已公开、新版待审 | 仅展示仍有效的旧版及日期，新附件不能泄漏 |
| 审核通过后、发布前作者撤回 | 发布事务重查revision/意愿，拒绝过期操作 |
| 任一必要许可撤回或到期 | 先阻断读取所有相关已发布版本，再清投影、搜索、推荐及分享预览 |
| 重新申请公开 | 再确认版本与授权，不能重放旧发布事件恢复 |

受控用户作品MVP使用no-store读取网关，不能静态构建全文或永久公开文件URL。浏览器已下载/截图副本不能保证远程删除，应告知。CP状态无法确认时作品内容不显示；与个人作品无关的已批准机构介绍可以按独立缓存策略继续展示。

### 5.2 活动与长期履历

Activity的审批/发布、生命周期、可见性、参与资格、报名模式分别建模；映射到现有status时不得丢失语义。角色确认、出席、实际贡献和核验等级分别记录。Call参加不消耗现场席位；收藏或外部链接访问不制造录取；出席不强制发证；贡献事实不等于评价结论。

来源可声明`claimedVerificationLevel`，Core按证据和被授权确认者产生`evaluatedVerificationLevel`。保存来源、issuer、确认者、时间、方法、实际单位与更正链；哈希仅校验内容一致。业务负面评价留项目私域，不自动成为公共信用记录。
