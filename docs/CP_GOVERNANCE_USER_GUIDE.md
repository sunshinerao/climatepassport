# CP 治理 User Guide

Last updated: 2026-10-01

依据：[CP业务规则主册](CP_BUSINESS_RULES.md)1.0及1.2工程细则。当前新增了有限的 Programme 治理运营工作台，但项目登记、来源绑定、身份绑定、规则编辑器和五站机器连接尚未交付。下面说明已验证业务行为，不能据此认为生产发奖已启用。

## 治理工作台：查看与运营

登录后从账户菜单进入“Programme 治理”。页面只列出当前账号通过有效 Programme-wide scope 获得读取权限的项目；全局 ADMIN 身份本身不增加项目可见范围。只读角色可以查看状态；具备 manage 权限的成员可按服务端状态机批准、发布或退役项目/规则，并处理或重试奖励任务。批准人与规则创建者相同时，服务端仍会拒绝批准。

奖励任务显示的状态不是推测结果：只有服务端返回 `SUCCEEDED` 且 `rewardSuccess: true` 才显示奖励完成。授权不足、奖励配置缺失或任务未到重试时间会显示服务端错误码，不应通过再次注册参与或重复来源事件规避。

此工作台暂不创建项目或规则，不配置来源、核验员、身份绑定或奖励定义。此类登记和编辑流程仍待治理网页后续阶段；外部站点消息、机器凭据、自动调度和生产发奖也未开放。

## 机构组织者：登记与规则

先登记所属机构和Programme下的一次可奖励单元／期次，获得统一编号。多个网站对应同一次单元时使用同一个编号；另一期活动需另登记，不能拿整个Programme代替具体单元。来源须明确业务权威、既有来源配置、经验证的人与记录映射。技术ADMIN本身不构成业务授权。

按该单元目的选择积分、徽章、证书，或不配置奖励；不用同时给三种。积分数额由规则定义。徽章须明确条件；证书须注明真实签发机构和参与、结业、能力类别。能力证书需评分条件，来源完成报告不会自动变成CP独立能力认可。签发须获机构授权代表许可。

提交另一名有Programme范围授权的审批者审批，再发布。批准后的内容不可编辑；规则变化另建新版本。签发方和模板随规则冻结，改模板不改变已批准版本。

## 审批者：入场、发布与退役

入场时为参与者固定已发布规则，早于首个事实。后来增加另一网站的记录仍使用同一版本。同一参与者同一单元每类奖励只有一次决策，不因不同网站重复获奖。本期重复参与政策尚未交付。

退役停止新入场；已入场者可以继续处理原规则下的合法历史纠错和撤销。纠错事实发生时间须满足原规则有效期，不能将今日提交纠错的时间直接填作原参与时间，也不能倒造同意。

## 核验员：提交事实与纠错

仅指定核验员且具Programme授权时可提交该来源事实。CP核对来源、经验证的身份绑定、记录、固定规则以及当前独立的资格用途同意。GCA样板为学习完成；FS样板为作品评审通过。未知字段、脚本条件或不支持奖励均拒绝。

事实受理表示资格任务已持久化，不表示奖励已发放。更正建立下一版本并指向当前版本；撤销采用最小控制消息，不重发作品或旧同意。重复同一不可变消息不会重复发奖，冲突内容拒绝。来源事实仍须真实，不因技术受理而成为CP独立评测。

## 参与者：资格、展示与撤回

资格判定、私密档案与公开展示分别管理用途。只有私密入档同意不能触发奖励资格。撤回资格同意会阻止尚未发出的新奖励，已正确发出的奖励不会仅因撤回展示而作废。

徽章和证书默认私密；公开展示由本人决定，技术管理员不能代替本人公开新治理凭证。关闭展示保留有效奖项。事实出错需要核验员纠错或撤销；若另一个受核验来源仍有有效依据，奖励保留。最后依据失效则先停止公开核验，积分冲正、徽章或证书撤销任务随后执行；撤销后的凭证不能重新公开。

## 管理者：待处理与失败恢复

检查持久化任务和实际奖项状态。PENDING表示待执行，RETRY表示可恢复失败，BLOCKED表示授权或配置不足，SUCCEEDED才表示任务完成，CANCELLED表示任务不再适用。发放失败不会部分记积分或制造成功凭证；恢复后只发一次。冲正保留原账本与依赖关系。

当前process/retry是有授权的后端操作，没有自动后台调度或新操作网页。未知条件的旧规则需重新检查并建立批准配置，不能悄悄修改冻结快照。旧活动仍有业务提交到任务创建的事务间隙，不能宣称所有旧业务已完整原子化。

## 验收与能力边界

真实隔离PostgreSQL服务验收21/21，包含故障回滚、跨源奖励、退役历史处理、真实PDF、本人展示及凭证撤销；完整回归818/818，类型与正常构建通过。此处不是浏览器全流程或多站真实HTTP资格验收。

尚未交付：新治理网页、五站资格机器鉴权和正式接入、自动调度、重复参与政策、生产启用。已有私密归档协议不获得新资格用途。历史有界GCA/FS窗口已关闭，旧凭据不会复用。

当前治理项目未支持Edition字段；机构代表权必须明确覆盖整个Programme（editionId为空），届次限定代表权不能扩大为跨期签发权。各期canonical单元仍须独立登记。
