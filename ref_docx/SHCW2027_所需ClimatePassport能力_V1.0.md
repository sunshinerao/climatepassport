## 1. 本文件的任务与边界

CP 是统一身份与行动指纹系统。SHCW 2027 需要调用 CP 的身份、主档、活动关联、参与服务、长期行动记录及授权展示能力。

本文件列出“CP 需要提供的结果”，不把全部能力都视为新建，也不宣称已完成生产验收。实施顺序为：核验现有实现 → 复用已稳定服务 → 修复相关缺口 → 补齐渠道契约 → 联合验收。

用户最新确认的职责：

- SHCW 持有活动举办申报、Speaker/Venue/Volunteer 申请、审核、退修、拒绝、邀约协商、场地筹备、排期和 Programme 内容。
- CP 持有身份、Person/Institution 主档、可复用参与服务，以及正式活动的关联、可追溯行动关系、关键里程碑、贡献、结果和证据。
- 正式获批的活动可在 CP 建立私有关联；公开展示随 SHCW 发布且受字段许可控制。
- 申请过程不进入 CP 行动履历。真正有长期意义的行动里程碑可在结果之前进入 CP，但必须标明“计划/确认/已发生/已核验”。
- 不创建第二套个人或机构主档，不把应用内角色变成 CP 全局权限。

该边界细化了 CP 当前文档中的 Core/Shell 描述：SHCW 增加私有的年度运营业务；CP 已有报名、学习申请等服务仍然保留。业务表单由哪个系统拥有，应按用途判断，不能因名称都含 Application 就归入同一域。

## 3. 数据进入 CP 的规则

| 数据 | 是否进入 CP | 条件 |
| --- | --- | --- |
| 个人、机构身份 | 是 | 使用既有主档及授权/认领规则 |
| 活动举办申请的草稿、表单、内部附件 | 否 | SHCW 保存 |
| 评审分数、内部意见、拒绝原因 | 否 | 不作为行动记录或公开档案 |
| 正式获批活动 | 是 | 唯一来源映射；未发布时默认非公开 |
| Programme 标题、时间、地点等 | 是，受控投影 | SHCW 为编辑权威，按版本更新 |
| 拟邀嘉宾、未确认合作机构 | 不作为正式关系 | 留在 SHCW 私有流程 |
| 已确认活动角色 | 是 | 记录确认依据、状态和公开许可；不能当作已完成 |
| 场地申请、报价、设备、内部联系人 | 否 | SHCW 场地运营 |
| 已发布活动的公开地点 | 是 | 不包含私人联系方式和私密地址 |
| 实际场地支持 | 可进入机构贡献 | 有机构主体、事实、来源及确认 |
| 收藏、报名、通行权益 | 由 CP 服务承载时是 | 默认私人交易/意向数据，不等于行动成果 |
| 实际出席、演讲、志愿服务、任务完成 | 是 | 证据、授权和等级校验通过 |
| 共同项目里程碑与成果 | 是 | 明确主体、责任、时间、来源、关联活动/项目 |
| 自报影响数字 | 可以，须单列 | 保留自报来源及方法，不自动升级核验等级 |
| SHCW 内部运营日志 | 否 | 双方仅共享必要关联 ID 和集成回执 |

存入 CP、在 CP 内授权使用、对外公开、形成核验背书是四个不同动作，必须分别控制。

## 4. CP 需要提供的能力

编号前缀 `CP-SHCW` 是本项目接口需求号，不替代或占用 CP 仓库既有 CP-TODO 编号。

### CP-SHCW-001 渠道身份认证与会话（G1 必需）

**结果：** 用户使用同一个 CP 身份进入 SHCW，并在返回原业务页面后继续操作。

提供：

- 可信用户主体引用、账号有效状态、最低必要显示信息及会话过期信息。
- 登录、注册、找回密码、退出和禁用状态的一致行为。
- 渠道/目标地址约束、请求与返回上下文关联、防重放及安全退出。
- SHCW 服务端验证当前身份的明确方式；不能只相信浏览器传来的 userId 或一次跳转成功。
- 对“用户操作授权”与“SHCW 服务账号发布活动”使用不同凭据和权限。

现有 v1 bridge/exchange 可复用，但当前代码描述的是 CP 浏览器会话签发与交换，不能直接认定任意域名间 SSO 已完成。需验证域名、Cookie、CORS、CSRF、返回地址和一次性消费的完整旅程。是否采用现有 bridge、服务端授权码或 OIDC 由实施设计决定，不要求为了本项目重写登录体系。

验收：同一身份无重复开户；过期和重复交换被拒绝；不能开放重定向；SHCW 不取得密码；注销/禁用后敏感操作不可继续。

### CP-SHCW-002 个人身份与 Person 主档（G1 必需）

**结果：** SHCW 可引用和展示获授权的个人信息，不维护另一套长期个人档案。

提供：

- 查询当前用户关联 Person 的最小资料，以及用途限定的头像、称谓、简介、职务和能力标签。
- 主档更正入口、版本标识、归属和可见性；SHCW 的申报快照不自动覆盖主档。
- 已确认但未开户嘉宾的受控 Person 创建/认领；区分用户账户和人员档案。
- 重复候选提示与人工合并治理；合并后旧引用可解析。
- 在特定活动/年度内，授权公开 Speaker 简介的投影能力。

边界：不提供可枚举全体用户的公开目录；不要求申请人公开全部 Portfolio；自填能力标签与经核验能力记录分开。

验收：同一个人可关联多场活动且不重复建档；无同意不返回邮箱等私有字段；代录 Person 不自动创建登录账号或发送未经请求的邀请。

### CP-SHCW-003 机构主档与代表权限（G1 必需）

**结果：** 主办方使用统一 Institution 引用，同时能够证明谁有权代表该机构提交或管理业务。

提供：

- Institution 最小资料、确认状态、稳定引用及更新版本。
- 机构查重、认领、主档更正或受控建立机制；避免 SHCW 新建平行机构库。
- 机构成员/代表权限的可信断言，或一个明确可验收的委托授权契约。
- 能区分员工任职、资料维护者、项目提交人、机构管理员，且支持权限撤回。
- SHCW 年度角色可以本地管理，但其机构授权依据应可追溯；不得从 CP 全局 UserRole 粗略推导。

现有 PersonAffiliation 不自动构成业务授权；现有 Organization 与 Institution 的兼容处理应由 CP 提供统一适配，不由 SHCW 自行合并。

验收：机构 A 的提交人不能操作 B；一人可以代表多个已授权机构；撤权后不能继续导出或修改；Logo 展示不等于已建立合作。

### CP-SHCW-004 正式活动接入与唯一映射（G2 必需）

**结果：** SHCW 批准并发布的正式活动在 CP 中成为唯一可关联对象。

提供：

- 用 `sourceSystem + sourceEditionRef + sourceEventId` 幂等创建/查询正式活动。
- 返回稳定 `cpActivityRef`（逻辑名）和版本/接收回执。
- 绑定来源系统、编辑权威、公开范围、原始官网链接及年度归属。
- 接收时间/地点/参与方式/主办关系等最小正式字段，支持跨日、时区和场次。
- 批准未发布可建立私有对象；未到发布条件不能被搜索或开放报名。
- 发布、改期、取消、下架、结束、归档的明确状态映射及入口联动。
- 区分“接收请求成功”“业务应用成功”“公开页面已可见”。

兼容要求：当前 CP 存在 Event 和 Activity。建议新 SHCW 渠道优先以 Activity 作为正式活动核心，由 CP 决定兼容适配；不得为同一活动同时新建 Event 和 Activity，导致报名或历史分裂。必须先给出旧 ID 对照与唯一记录规则。

验收：超时重试和并发首次发布只有一条记录；旧版本不能覆盖新版本；取消阻止新报名；无权来源不能修改其他渠道活动。

### CP-SHCW-005 活动与角色的受控公开展示（G2 必需）

**结果：** CP 能展示 SHCW 正式活动及已授权关系；SHCW 可展示 CP 主档的必要投影。

提供：

- 按 Edition 获取公开活动目录和详情，注明 SHCW 来源与返回官网链接。
- 活动角色关系：主办机构、协办机构、演讲、主持、场地支持等；角色和履行状态独立。
- 确认、取消、已履行的状态；“计划参与”不计入已完成贡献。
- 公开投影只含年度、活动、角色和获授权人物/机构字段。
- 更新许可、取消角色、下架活动后，公开缓存可撤销或失效。
- 同一人多角色时保存关系，而非覆盖全局身份。

不提供：SHCW 私有 Speaker Pool 全量查询、所有人员公开检索、内部评审或邀请条件披露。

验收：私人候选人不可见；活动已发布也不强制公开其所有参与者；角色撤回后官网/CP 不继续显示为已确认；未举行活动显示计划状态。

### CP-SHCW-006 报名、收藏、日程与资格服务（CP 报名模式在 G2 必需）

**结果：** SHCW 调用 CP 已有参与服务，不建立第二套报名权威状态。

提供：

- 当前用户收藏、取消收藏、日程查询和日历导出所需数据。
- 报名、取消、审批、候补、容量、截止时间、邀请资格及明确状态查询。
- 返回用户级报名与权益，不将私有名单混入公开活动 API。
- 活动管理者获取授权范围内名单、审批和最小化导出；区分管理权与人员身份。
- 外部报名和免报名活动的非交易展示状态；可接受经约定流程确认的外部参与证据。
- 更新活动日期、取消后联动日程、入口和必要通知。

现有 ActivityApplication 是参与申请基础，不接收 SHCW EventSubmission（举办申报）。CP 内部使用哪个表由 CP 决定，渠道只依赖稳定状态语义。

验收：容量并发不超限；同一用户重复请求不产生多份报名；待审批无入场资格；点击外链/收藏不变成 REGISTERED；导出严格按活动资源与字段许可。

若 CP 报名渠道尚未验收，正式上线只能启用已声明的 EXTERNAL/NONE 模式或关闭报名，不能在 SHCW 临时复制一套 CP 报名系统并声称已统一。

### CP-SHCW-007 通行证、二维码与现场核验（G3 必需）

**结果：** 使用 CP 唯一凭证和核验规则形成可信出席证据。

提供：

- 当前用户、指定活动和资格范围内的通行证/opaque QR。
- 服务端鉴别核验员、活动范围、用户资格、凭证状态及有效窗口。
- 并发签到、重复扫描、手动补录、更正和审计规则。
- 只有服务端成功核验后更新参与状态及触发已批准奖励规则。
- 多日活动按实际需求定义“入场一次”“逐日签到”“完成课程”的不同语义，不把它们混用。

复用 CP 现有无年份 Passport ID 和 opaque token 设计；不使用 `SCW2026://...` 示例作为新的 CP 凭证，不在二维码暴露姓名、邮箱、裸数据库 ID。

验收：未分配核验员、不同活动、撤销/过期/重复凭证被正确处理；旧 direct/checkin 等兼容入口也受相同规则约束；网络故障不显示已完成核验。

### CP-SHCW-008 行动事实、贡献与证据接入（最小模型 G2；业务闭环 G4）

**结果：** SHCW 可提交经确认的行动事实，CP 决定如何形成长期履历。

最小记录需表达：

| 字段组 | 要求 |
| --- | --- |
| 谁 | Person / Institution 稳定引用；支持机构贡献，不仅是 User 积分 |
| 在哪里/何时 | CP 活动/项目引用、实际发生时间和时区 |
| 做了什么 | 角色、行动类型、事实摘要、计划/确认/已发生/完成状态 |
| 有什么证据 | 来源系统、源记录 ID、出具者、确认时间、受控证据引用 |
| 可信程度 | 本人声明、主办方确认、第三方核验等；与 CP 现有等级映射 |
| 谁能看 | 私人、指定组织/渠道、公开；用途及同意记录引用 |
| 如何追溯 | 版本、签发/确认主体、更正/撤销关系、接收/应用回执 |

- 支持参会、发言、主持、志愿服务、场地支持、共同任务、成果发布等可配置类型。
- 不要求把 SHCW 内部所有任务同步；只有有明确意义、责任主体和证据的里程碑进入。
- SHCW 只能提交其授权范围内事实；CP 不接受客户端直接设置“已核验”、积分、证书状态。
- 同一人同一活动的多种角色/贡献可分别关联，不能受单一 roleType 限制而相互覆盖。
- 从现有 Participation、PassportMilestone、Achievement 等基础设计适配；不因出现新术语就再建一整套平行履历库。
- 外部证据到达只是收件；身份映射、校验、确认及应用完成后才进入对应记录。

验收：自报证据不会自动升级第三方核验；未完成者不生成完成记录；机构场地贡献可追溯；跨入口重复上报不重复计数；不能以活动总时长直接给所有人发学习时长。

### CP-SHCW-009 授权、可见性、更正与撤销（G1 基础；G2/G4 按功能完成）

**结果：** CP 数据可按用途共享，失效记录和撤回许可能正确影响展示。

提供：

- 用途限定的读取与公开展示许可，记录主体、接收方、字段、用途、版本、时间和状态。
- 主档、私有参与、公开 Speaker 简介、证据和个人 Portfolio 分别控制。
- Portfolio 继续采用既有可撤销 token 机制；不开放按 Passport ID 枚举个人履历。
- 将“撤回公开许可”“更正事实”“撤销凭证”“删除账号”区分处理。
- 记录错误、活动取消、贡献否认、证据撤销的受控更新及审计。
- 公开投影/cache 失效，以及通知获授权接收方停止使用的机制。
- 法定/合同保留等规则由相关负责人配置；追溯性不等于无限期保存所有个人材料。

验收：撤回许可后分享和投影不继续曝光；权限过期的证据 URL 不泄露；事实更正后汇总和凭证有效性一致；不得仅删除日志来掩盖错误。

### CP-SHCW-010 渠道契约、对象授权与可靠同步（G1/G2 必需）

**结果：** 以稳定 API/SDK 或托管流程服务 SHCW，并能可靠处理网络和状态差异。

提供：

- 按渠道、Edition、机构、活动的服务端资源授权；普通 SHCW 操作不能拥有 CP 全平台权限。
- 机器调用凭据保存在服务端；用户调用必须保留实际操作者与授权上下文。
- 字段白名单、输入验证、稳定错误码、分页、时区、版本、关联请求 ID 和兼容策略。
- 幂等键、源记录唯一约束、版本冲突处理、持久回执和对账查询。
- 变更通知采用签名校验、时间窗口、去重、防重放、重试和失败队列；无 webhook 时必须提供等价的增量对账机制。
- 同步允许短暂不一致，但状态可见；取消/撤权优先处理；各类缓存失效有上限。
- 针对源字段只接受源系统版本推进；对 CP 自有的签到/凭证状态禁止 SHCW 随意覆盖。
- 日志脱敏、权限审计、限流与生产配置清单。

验收：重复、乱序、超时、部分成功、凭据撤销、跨机构/年度请求全部有确定结果；内网表结构不作为对接契约；浏览器不直接访问 CP 数据库或全权限 API Key。

### CP-SHCW-011 履历、凭证及年度汇总（G4；可选凭证按启用范围）

**结果：** 有效的行动记录可被本人管理，并按授权用于 SHCW 成果展示。

提供：

- 本人/机构的长期行动记录，按年度、活动、角色和有效状态检索。
- 与现有里程碑、成就、徽章、证书、Portfolio 的关系；不要求每个行动都发证或积分。
- 如启用积分/证书，规则有负责人、版本、触发证据和撤销/补偿语义。
- 可授权的年度活动数、人次、去重人数、已确认贡献/成果等汇总，标明统计范围、来源、时间和去重规则。
- CP 核验、自报、外部系统数据分别汇总；跨域无法可靠去重时不声称全域唯一人数。

现状限制：CP 审查记录证书最终 PDF 交付仍有差距；SHCW 未启用证书时不把修完全部证书模块列为网站上线前置，启用“下载 PDF”则必须验收真实 PDF，不能以 HTML 打印页替代。

验收：取消/更正/撤销影响有效统计；同一事实不双倍奖励；公开汇总不能反查完整私有名单；没有证据和核算方法不生成减排量。

### CP-SHCW-012 联调环境、文档与运行支持（G0 起，贯穿各门槛）

**结果：** SHCW 团队可以独立实现和验证接入，且问题可定位到明确责任方。

交付包：

- 已有/部分/缺失/待验收能力清单，含代码指针和环境证据日期。
- 可用测试环境、实际 base URL、渠道启用配置和测试角色；不在文档提交凭据。
- 版本化契约、OpenAPI 或等价机器可读描述、SDK 示例、错误码和最小字段权限表。
- 测试活动/Person/Institution 的受控样例、权限反例、重复/乱序/故障测试方法。
- Event/Activity 与历史身份映射说明，不要求 SHCW 猜测数据模型。
- 域名/回调/Cookie/允许来源配置矩阵，区分本地、测试与生产。
- 接收/应用回执、状态查询、重试对账和监控告警说明。
- 上线/回滚/数据纠错步骤和双方维护责任；不以测试环境通过证明生产已开通。

## 6. 最小交换数据结构

以下为逻辑字段说明，不是最终接口 JSON，也不要求全部创建新数据库列。

### 6.1 正式活动投影

必需：sourceSystem、sourceEditionRef、sourceEventId、sourceVersion、title/locale、startAt/endAt/timezone、publicationState、eventState、sourceUrl、registrationMode、organizerRefs。

按需：公开地点、概要、主题/标签、语言、容量、费用说明、已确认角色、来源确认时间、公开字段许可版本。

不得包含：举办申报全文、审核分数、拒绝原因、内部预算、场地报价、私有联系人、未获授权的拟邀名单。

CP 返回：cpActivityRef、acceptedSourceVersion、receiptId、processingState、appliedAt 或结构化错误。

### 6.2 行动/贡献事实

必需：sourceRecordId、sourceVersion、cpActivityRef 或项目引用、subjectType/subjectRef、actionType、occurrenceState、occurredAt、issuerRef、claimedVerificationLevel、evidenceRefs、visibility/purpose。

按需：role、实际时长/数量及单位、方法说明、确认者、成果链接、consentRef、correctsRecordRef、撤销原因分类。

接收方必须验证 claimedVerificationLevel，不能把来源的主张当作 CP 自身核验结论。CP 返回独立的 evaluatedVerificationLevel、recordState 和记录引用。

### 6.3 证据与授权

- 证据引用用稳定 ID/受控资源定位，不能把临时签名 URL 当长期证据身份。
- 如需防止内容被替换，可记录内容摘要/哈希与版本；哈希只说明内容一致性，不证明事实真实。
- 原始附件可由 SHCW 保管，CP 保存可授权解析的引用；少量长期必要证据是否归档，由保留政策和服务契约决定。
- 公开数据、接入处理数据、本人私有数据和内部审计分层，不能把“进入 CP”等同于“全部公开”。

## 7. 可靠性与状态一致性

推荐出站流程：SHCW 业务状态与出站任务在本地事务中保存 → 后台发送 → CP 幂等接收 → CP 应用 → 返回/查询回执 → SHCW 更新同步状态。

| 情况 | CP 必须提供的结果 | SHCW 配合行为 |
| --- | --- | --- |
| 同一发布重复投递 | 相同映射；不能重复建活动 | 重用幂等键和源版本 |
| 同键不同内容 | 明确冲突，不静默覆盖 | 修正版本后重提 |
| v3 先到、v2 后到 | 拒绝旧版本或确认无效 | 标记旧任务完成/过时 |
| 活动发布成功，角色同步失败 | 活动回执与角色失败分别可查 | 只重试未完成部分 |
| 网络超时但已写入 | 可按源键查询成功回执 | 先查询/幂等重试 |
| 活动取消 | 关闭后续报名，更新公开状态 | 本站即时关闭入口并优先投递 |
| 同一签到由两条入口触发 | 统一领域约束，记录/奖励去重 | 不自行再写行动完成 |
| 同意撤回/证据失效 | 私有保留策略与公开失效分开 | 清理公开缓存/链接 |
| CP 暂时不可用 | 明确错误，不返回伪成功 | 保留出站任务并显示待同步 |

不要求跨库分布式事务。应以幂等、唯一键、回执、重试和对账实现可解释的最终一致性。建议正常发布同步目标 60 秒、5 分钟异常待办，与 SHCW 文件一致，须在联调确定可履行的服务目标。

## 8. CP 明确不需为本项目建设的内容

1. SHCW 主办方的活动举办申请、评审、退修、拒绝和内部审批后台。
2. SHCW Speaker 候选池的申请审核、人工撮合、差旅和邀约谈判流程。
3. 场地征集、报价、档期、合同、设备和空间预订系统。
4. 志愿者招募筛选、请假排班和内部人员评价。
5. 年度新闻、品牌页面、媒体包及整套 SHCW CMS。
6. 将申请失败、内部评价或商业谈判自动写成个人/机构行动履历。
7. 为本项目新增生物指纹、区块链、DID/VC、AI 自动评分或自动核验。
8. 为展示一个年度网站而先拆成多个独立部署或迁移所有历史业务。

这些排除项不否定 CP 已有其他产品模块；只界定 SHCW 2027 对 CP 的需求边界。

## 10. CP 与 SHCW 联合验收

| 用例 | 验收结果 |
| --- | --- |
| CP-AC-01 真实域名登录与回跳 | 同一主体、正确上下文、跨域策略有效；重放和错误目标被拒绝 |
| CP-AC-02 主档与机构代表权 | 只返回许可字段；未授权任职不能代表机构操作 |
| CP-AC-03 私有申报隔离 | CP 请求与数据库中不出现 SHCW 举办草稿、拒绝理由或场地报价 |
| CP-AC-04 批准与发布分离 | 已批准未发布仅私有；发布后两站可见且来源明确 |
| CP-AC-05 活动唯一性 | 并发、重试、超时恢复均只产生一个核心活动引用 |
| CP-AC-06 新旧模型兼容 | 一个 SHCW 活动不能因 Event/Activity 并存获得两套报名或积分 |
| CP-AC-07 修改、取消、下架 | 来源版本正确，报名入口及缓存符合状态 |
| CP-AC-08 Speaker 多角色与许可 | 私有候选不可见，确认不算完成，多角色无覆盖 |
| CP-AC-09 容量与资格 | 并发报名、候补、审批、邀请资格及撤销一致 |
| CP-AC-10 核验资源授权 | 未分配、跨活动、旧入口均不能绕过；双扫码不重复发放 |
| CP-AC-11 个人与机构事实 | 实际发言、志愿时长、机构场地支持均有来源与等级，不伪造减排 |
| CP-AC-12 外部证据 | 收到负载不直接标为已核验；无法认领/映射时保留待处理 |
| CP-AC-13 隐私和撤回 | 分享撤回、证据失效后公开投影和有效汇总更新 |
| CP-AC-14 奖励/凭证可选 | 未启用不自动发；启用后以有效证据触发且重放不重复 |
| CP-AC-15 年度统计 | CP 核验、自报、外部来源分列；重复与撤销可复算 |
| CP-AC-16 故障与对账 | 重试、乱序、部分失败可恢复，前台不把待同步当成功 |
| CP-AC-17 跨年度与渠道隔离 | 只凭 SHCW 权限不能读取/修改其他年度或渠道私有记录 |
| CP-AC-18 历史连续性 | 不重发既有 Passport ID，不丢失历史参与，旧引用有兼容映射 |

每项标明证据环境与时间。代码存在、mock 通过、局部 API 测试、浏览器联调和生产验收须分别记录。不得照抄 CP 历史“测试全部通过”作为本集成已通过证明。
